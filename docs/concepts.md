# Core Concepts

*The vocabulary and invariants of `concursus`: DAG, manifest, plan, state, trust, governor, reasoning.*

This is a reference glossary. Every term below belongs to exactly one tier, and every tier obeys the one load-bearing rule: **Concursus is a compiler, not a runtime governor.** A run is `AgentDAG → assemble → frozen ProvisioningPlan → Supervisor.run` — a single forward pass over an immutable plan. Everything generative (reasoning, planning, a governor round) happens *strictly before* `assemble`; everything after it is replay. Terms are grouped by the tier that owns them, defined in a sentence or three, and linked to their reference doc, their guide, and their source module. The [Invariants](#invariants) section at the end states the load-bearing rules verbatim.

New here? Start with the [Overview](overview.md) for the mental model, then [Getting Started](getting-started.md) to compile and run a team. This page is the dictionary you return to. See the [documentation index](README.md) for the full set.

## Core: the declarative unit

The pure, backend-agnostic heart — no AWS, no LLM. See [API Reference: core](reference/core.md) and the [Authoring Agents guide](guides/authoring-agents.md).

**AgentDAG** — A directed acyclic graph whose nodes are agent/task ids and whose edges are data dependencies: an edge `a → b` means *b depends on a* (a is the upstream producer). It is built fluently (`add_node`, `add_edge`), rejects cycles and self-loops, and produces a deterministic dispatch order via `topological_sort()` (Kahn's algorithm, lexicographic among concurrently-ready nodes). Its `nodes` property returns ids in that **topological** (dispatch) order — producers before consumers, ties by name — not a plain alphabetical sort; it falls back to a name-sort only for a cyclic graph so `nodes` never raises (cycles are still rejected by `validate` / `topological_sort`). `add_node(name)` takes only a node id — edges are declared separately with `add_edge`, and the typed interface lives on the manifest, not the DAG. This is the topology the whole pipeline compiles from. Source: [`core/dag.py`](../src/concursus/core/dag.py).

**AgentManifest** — The parsed representation of one agent's `.agent.yaml`: its AgentCore hosting binding (`registry`), its typed interface (`contract`), its author-declared dependency edges (`spec.depends_on`), and deploy-gate metadata (`trust_seed`, `side_effecting`, `escalate_boundary`). `name` is the unique node id in an `AgentDAG`. `from_dict`/`from_yaml` build it (yaml imported lazily); `validate()` enforces the contract but is never called automatically. Source: [`core/manifest.py`](../src/concursus/core/manifest.py).

**Output-JSON-Schema type gate** — Every manifest MUST declare a non-empty output schema (`contract.outputs`, surfaced as `AgentManifest.output_schema`). This is mandatory because it is the dependency resolver's type gate: resolution is meaningless without knowing what each producer emits. `validate()` rejects a manifest whose output schema is empty. See [authoring-agents.md](guides/authoring-agents.md).

**Agent capabilities, contract-version pin & context-mode (opt-in manifest metadata, all default-inert)** — Three OPTIONAL `AgentManifest` fields the compiler *stores and shape-validates* but takes no runtime action on; each empty default is byte-for-byte identical to a manifest declaring it nowhere. **`capabilities`** is a frozen `AgentCapabilities(features, tools, egress_hosts)` — a purely-declarative attestation of what an agent's runtime provides (documentation, not a runtime governor); the empty default is *falsy* (`bool(AgentCapabilities()) is False`), so the governor registry's capability-derivation fallback is unchanged. **`contract_version`** is the `.agent.yaml` schema revision the manifest was authored against (defaults to `MAX_SUPPORTED_CONTRACT_VERSION`, currently `1`); `validate()` **fails closed** if the pin exceeds what this compiler supports (the manifest was authored against a newer compiler). **`context_mode`** is the per-agent content-reuse policy — one of `CONTEXT_MODES` (`""` = INHERIT, the default; `"reuse"` = this node's prior content may be reused; `"isolation"` = always re-provision); the empty default is pure inherit (defer to a team/group default, then a hardcoded `"isolation"` floor, via `resolve_context_mode`) and takes no action on its own. Source: [`core/manifest.py`](../src/concursus/core/manifest.py).

**AgentRef** — A frozen, resolved wire: `AgentRef(producer, path, input_name)` routes a producer's output value (read at minimal JSONPath `path`, e.g. `$.summary`) into a consumer's input field `input_name`. These are the point-to-point data edges the `Supervisor` uses at run time to build each invoke payload. Source: [`core/resolve.py`](../src/concursus/core/resolve.py).

**resolve / check_alignment** — `resolve_edges(dag, manifests)` compiles every node's `depends_on` edges into `AgentRef` wiring (an entry for *every* node, empty list when it has no deps). `check_alignment(dag, manifests, *, strict_types=False, single_writer=False, strict_fn=None, full_input_cover=False, require_capabilities=False)` is the separate type-gate: it returns `None` on success or raises `AlignmentError` on the first edge whose producer, referenced output field, consumer input, or matching DAG edge does not line up. They do not cross-check each other — you run `check_alignment` to type-gate. Source: [`core/resolve.py`](../src/concursus/core/resolve.py).

**The compiler contract (opt-in gates, all default off)** — the name-level gate above is always on; several deeper properties can be dialed on at compile time and are byte-for-byte no-ops when off. **(1) Non-overlap** (`single_writer=True`): no consumer input may be fed by more than one `depends_on` edge — two edges into the same `input_name` are a silent last-wins overwrite at run time, and the gate raises a "single-writer violation" instead. **(2) Deep type-alignment** (`strict_types=True`): a producer output field's declared JSON-Schema `type` must be compatible with the consumer input's declared `type`, or `AlignmentError` is raised; it is conservative (an unknown/absent type on either side passes, and union types like `["string","null"]` are matched by set-overlap). **(3) Full-input-cover** (`full_input_cover=True`): every declared `contract.inputs` key must have a compile-visible supplier — a `depends_on` edge or a static `contract.context` key. **(4) Output-QA** is the run-side property — see `check_acceptance` in [Execute](#execute-the-single-forward-pass). All compile-time gates are compile-time only (INV-2) and default off. A `strict_fn` (`Optional[Callable[[str], bool]]`) narrows `strict_types` / `single_writer` to the nodes it returns truthy for (`None` = every node); it never relaxes the name-level gate. On an edge-specific failure `AlignmentError` carries answer-carrying attributes (`.node` = offending consumer, `.producer`, `.field`, `.expected`, `.candidates`) so a re-binder can target the fault without parsing the message (all `None` for non-edge failures; the positional-message constructor is back-compat). Source: [`core/resolve.py`](../src/concursus/core/resolve.py).

## Assemble: the offline compiler

Turns a DAG + manifests into a frozen, previewable plan — pure, never touches AWS. See [API Reference: assemble](reference/assemble.md) and the [Compiling & Running guide](guides/compiling-and-running.md).

**OrchestrationAssembler** — The compiler. `assemble(dag, manifests)` validates the DAG and each manifest, type-gates edges via `check_alignment`, resolves wiring, synthesizes one `BuildPlanEntry` per node, topologically orders the nodes, and freezes everything into a `ProvisioningPlan`. It never imports boto3; `account`/`region` are threaded into synthesized IAM roles only so the plan previews ahead of a real deploy. `OrchestrationAssembler(..., strict_types=False, single_writer=False, strict_fn=None, full_input_cover=False)` threads the [compiler-contract](#core-the-declarative-unit) flags into both `assemble` and `recompile`; all default off, so the compiled plan is byte-for-byte unchanged. Source: [`assemble/assemble.py`](../src/concursus/assemble/assemble.py).

**ProvisioningPlan** — The compiled plan for one agent team: `order` (topological dispatch order), `entries` (`{node: BuildPlanEntry}`), `wiring` (`{node: [AgentRef,...]}`), optional read-only `precedents`, a `revision` counter, and a read-only advisory `frontier` list (default empty). Treated as an immutable frozen preview. `to_dict()` renders the full JSON preview (`precedents` only when non-empty, `revision` only when non-zero, `frontier` only when non-empty — so the default is byte-for-byte unchanged); `to_summary_dict()` renders a compact hosting digest for a durable plan note. Source: [`assemble/assemble.py`](../src/concursus/assemble/assemble.py).

**Monotonic recompile** — `OrchestrationAssembler.recompile(prior_plan, *, completed, content_hashes=, dag=, manifests=, max_revisions=16, compile_next=)` is the *only* sanctioned plan mutation. It emits a fresh frozen superset plan (`revision = prior + 1`) that pins already-executed nodes to their prior entries/wiring and rejects any edit, removal, or reorder of an executed or already-planned node (`MonotonicityError`). It is bounded (the revision cap) and never mutates `prior_plan` — the feedback edge lives *around* the compiler, never inside a running `Supervisor`. The opt-in `compile_next` kwarg (default off) records the scheduler's cleared frontier onto the fresh plan's read-only advisory `frontier` field (filtered to topology nodes); it never changes `order`/`entries`/`wiring`, so the monotonic superset is preserved. This closes the previously-dead scheduler → compiler channel. See [compiling-and-running.md](guides/compiling-and-running.md). Source: [`assemble/assemble.py`](../src/concursus/assemble/assemble.py).

**plan_from_goal** — `plan_from_goal(goal, *, precedents=, operator_directives=, plan_model_fn=, decompose=False, max_nodes=12, max_depth=6, max_fanout=6)` is the compiler's generative *front*: it authors an `AgentDAG` from a free-text goal exactly once at compile time. With no `plan_model_fn` it falls back to a deterministic single-node template (so the package runs with zero LLM); with one injected, the model returns a `{nodes, edges}` spec that is lowered into a DAG. It emits pure topology only — alignment and wiring gating are the assembler's job. Source: [`assemble/planner.py`](../src/concursus/assemble/planner.py).

**Goal decomposition (opt-in, default off)** — Set `decompose=True` and `plan_from_goal` will decompose a goal into a *multi-node capability DAG* instead of the single-node fallback. With no `plan_model_fn` it emits a deterministic, offline, linear capability chain (fan-out 1, bounded depth): node ids are agent-agnostic capability labels of the form `<goalslug>__<stage>` (they always contain `__` and never carry an agent or manifest name), keyword-routed by priority: a keyword match (`_SHAPE_KEYWORDS`) wins first; else, when `precedents` are supplied, the decomposer **borrows the capability-stage shape from the most-relevant precedent's executed `nodes`** (stripping each `<prefix>__<stage>` down to `<stage>` and re-prefixing to the new goal — a precedent-priming warm start for a novel domain); else it falls back to a generic `ingest → analyze → synthesize → format`. An unusable precedent (no multi-stage capability shape) is simply ignored, and the whole path is deterministic/offline. The goal-slug prefix is `rstrip("_")`-ed before the `__<stage>` join, so a goal whose 24-char truncation ends in `_` yields `…checkout__scope`, not a spurious `_scope` stage. The per-sub-task complexity contract `max_nodes` (12) / `max_depth` (6) / `max_fanout` (6) is enforced at author time — an over-budget DAG raises `PlanAuthorError`. `decompose=False` is the default and is byte-identical to the prior single-node behavior; an injected `plan_model_fn` always overrides the template even when `decompose=True`. Source: [`assemble/planner.py`](../src/concursus/assemble/planner.py).

## Build & deploy: standing up runtimes

Compile-then-deploy for per-agent AgentCore runtimes. See [API Reference: build](reference/build.md) and the [Deploying to AgentCore guide](guides/deploying-to-agentcore.md).

**RuntimeBuilderFactory / BuildPlanEntry** — `RuntimeBuilderFactory.synthesize(manifest, ...)` compiles one manifest into a `BuildPlanEntry`: the serving wrapper `app.py`, container `Dockerfile`, IAM execution-role doc, the `create_agent_runtime` param dict, an `invoke` descriptor, and a hosting-identity `fingerprint`. It dispatches per serving protocol (HTTP/MCP/A2A, one fixed port each) via a template, or registers a prebuilt image / existing ARN as-is. Pure and offline — renders artifacts and param dicts, never calls AWS. Source: [`build/build.py`](../src/concursus/build/build.py).

**provision_plan** — `provision_plan(plan, ...)` and `provision_agent(entry, ...)` are the deploy-time *actuator* — the only code that talks to AWS and Docker. Per node in topological order it ensures the IAM role, builds+pushes the ECR image (linux/arm64), calls `CreateAgentRuntime`, and polls to `READY`. It is partial-result safe: a `ProvisionError` or raw AWS error becomes a per-node `{"action": "failed"}` result and the accumulated list is always returned. Source: [`build/provision.py`](../src/concursus/build/provision.py).

**Trust Ladder (create-time deploy gate)** — The pure `evaluate_deploy_gate(*, side_effecting, trust_seed, min_autonomy=, require_approval=)` decides `live` | `shadow` | `hold` for one node, consulted **exactly once per node per deploy** — never per invocation. A `TrustGrade` seed (declared by the author, or a floor required by the operator) is graded against caller policy into a frozen `GateDecision(mode, qualifier, reason)`. This is the *create-time* gate; the runtime, per-decision ladder is the governor's [`TrustLadderScheduler`](#governor-runtime-governance). Source: [`build/trust.py`](../src/concursus/build/trust.py).

| Grade | Value | Meaning |
|---|---|---|
| `L0_SHADOW` | 0 | Cleared to run, but only in shadow |
| `L1_CANARY` | 1 | Canary autonomy |
| `L2_GUARDED` | 2 | Guarded autonomy |
| `L3_AUTONOMOUS` | 3 | Full live autonomy |

`TrustGrade` is an `IntEnum` (so grades compare with `<`/`<=`). Gate outcomes: a non-side-effecting node is always `LIVE`; with no caller policy the result is always `LIVE`; `require_approval` `HOLD`s any side-effecting node; a seed below `min_autonomy` `HOLD`s; a cleared floor seeded only at `L0_SHADOW` yields `SHADOW`; otherwise `LIVE`.

**DeployLedger** — A persisted, JSON-backed, append-only record keyed by `(name, fingerprint)` that answers one create-time question: *"have I already stood up this exact content?"* If yes, deploy skips build + `CreateAgentRuntime` and reports `action="reused"`, even across separate CLI invocations. It is persistence-only (no dispatch-time queries), append-only for audit (newest row wins on lookup), and disposable — the file is the source of truth and deleting it loses no canonical state. Source: [`build/ledger.py`](../src/concursus/build/ledger.py).

> The `fingerprint` covers only *hosting identity* (image/protocol/entrypoint/role/input-keys/output-schema) — it is deploy-dedup metadata and is **never** a dispatch-time version selector.

## Execute: the single forward pass

Drives a frozen plan to completion. See [API Reference: execute](reference/execute.md) and the [Compiling & Running guide](guides/compiling-and-running.md).

**Supervisor** — `Supervisor(plan, manifests, ...)` walks `plan.order`, builds each node's invoke payload from external inputs overlaid with resolved upstream outputs (`plan.wiring`), calls an injectable `invoke_fn` transport, shape-checks the result against the manifest's output schema (`validate_output` / `SchemaError`), and threads validated outputs forward through a `StateStore`. `run(inputs)` is a single static forward pass — it never mutates the plan. Structural validation (dangling `AgentRef`, cycle) runs once at construction. The invoke transport is one of the transport shapes AgentCore exposes (HTTP `/invocations`, MCP `/mcp`, A2A) — the default `invoke_fn` lazily binds boto3's `bedrock-agentcore` data-plane client, so importing the module needs no AWS SDK. Source: [`execute/supervisor.py`](../src/concursus/execute/supervisor.py).

**Output-QA + boundary gates (opt-in, default off)** — `Supervisor(..., check_acceptance=False, acceptance_fn=None)` adds the contract's run-side output-QA property. When `check_acceptance=True`, after `validate_output` the supervisor runs two deeper gates on the invoke result, riding the existing retry/record path (a miss raises under `on_error='raise'`, records-failed under `'record'` — a failing output is *not* admitted, does not complete, and earns no trust). **`check_hive_contract(obj)`**, checked first, enforces the agent↔OS-layer boundary: the output must be JSON-serializable (`json.dumps`) so the append-only log / `content_hash` can store it — a non-JSON output (a set, a bespoke object) that previously passed `validate_output` then crashed the log write now raises `SchemaError` legibly at dispatch. **`check_acceptance(obj, schema)`** then enforces each output field's declared `acceptance` mapping — `non_empty`, `min_length`, `max_length`, `enum`, `pattern` — declaratively and deterministically (no code eval); a present-but-wrong output raises `SchemaError`, while a field with no `acceptance` mapping is unconstrained. `acceptance_fn` (`Optional[Callable[[str], bool]]`) narrows the QA gate to selected nodes (`None` = every node). Default `check_acceptance=False` runs byte-for-byte unchanged. Source: [`execute/supervisor.py`](../src/concursus/execute/supervisor.py).

**runtimeSessionId session affinity** — One stable `runtimeSessionId` (`Supervisor.session_id`, at least 33 chars) spans *every* invoke in a run. It is the key under which a `MemoryStateStore`'s events are written, so replay-resume finds the same session. Source: [`execute/supervisor.py`](../src/concursus/execute/supervisor.py).

**Resume-by-skip** — On `run`, a node already in `store.completed()` is skipped (its output is replayed from the log, not recomputed); a node whose upstream producer has not completed records a `"blocked on <producers>"` failed skip; a node in the opt-in `held` set is a pure non-dispatch (never invoked, nothing written). This is how a partially-completed run resumes without re-planning: replay the append-only log, dispatch only the pending frontier. The opt-in `verify_plan_identity` guard persists the frozen plan's content-hash (`plan_fingerprint`) on the first pass and asserts it still matches before any resume skip — a divergent plan raises `PlanIdentityError` instead of silently mis-replaying a recorded node. Source: [`execute/supervisor.py`](../src/concursus/execute/supervisor.py).

**Bounded antichain-parallel wave (opt-in, `parallel=1` default)** — `Supervisor.run(inputs, *, parallel=1)` is a single static pass over the frozen `plan.order`; at the default `1` it is EXACTLY the serial pass, byte-for-byte unchanged. At `parallel > 1` each round dispatches the current ANTICHAIN — every still-open node whose `plan.wiring` producers are ALL completed — concurrently on a bounded `ThreadPoolExecutor(max_workers=parallel)`, waits for the wave, then recomputes; it loops until every node is completed or none is dispatchable. It is NOT a new execution model: the frozen `plan.order` is never mutated or replanned, a node dispatches only after all its producers complete, and results are keyed by node id — so per-node outputs, statuses, `consumes` edges and content hashes are byte-for-byte identical to the serial run (only store-local `seq`/`timestamp` reflect physical put order). `on_error` semantics, resume=replay, and the held/blocked skips are unchanged. Source: [`execute/supervisor.py`](../src/concursus/execute/supervisor.py).

**min(pref, capacity) fan-out clamp** — A requested `parallel` is CLAMPED by host CPU capacity via the SAME `resolve_ceiling(pref, cap) = max(1, min(pref, cap))` shape the inner graph uses for its investigator fan-out — where `cap = _cpu_capacity()` is the CPU count hard-bounded by `MAX_FANOUT_CAP` (`64`). A soft `parallel` request can only TIGHTEN the pool below the host's capacity, never spawn more workers than the host can serve. It shrinks only the worker-pool WIDTH, never the set of nodes dispatched, so the store contents stay byte-for-byte identical to the serial pass — determinism is untouched. Sources: [`execute/supervisor.py`](../src/concursus/execute/supervisor.py), [`reasoning/inner_graph.py`](../src/concursus/reasoning/inner_graph.py).

**Node-executor registry (opt-in Strategy/Registry seam)** — `NODE_EXECUTORS` maps a node-kind key to a uniform `(supervisor, node, inputs, wiring) -> None` handler. The shipped registry carries only `_DEFAULT_NODE_KIND` (delegating verbatim to `Supervisor._dispatch`), so with no custom kind selected every node routes to the default handler and the run is byte-for-byte unchanged. A caller may register custom kinds (`Supervisor(..., node_executors=)`) and select one per node (`node_kind_fn=`); a kind with no registered handler falls back to the default. Every handler shares the identical store/`on_error` path and never mutates the frozen `plan.order` (INV-3). The **runtime stack below** (invoker → monitor → harness) is the shipped custom kind that plugs into exactly this seam — it runs INSIDE the governed dispatch, never around it, so the compiler-not-runtime-governor invariant holds. Source: [`execute/supervisor.py`](../src/concursus/execute/supervisor.py).

**AgentInvoker + its backends (the harness-path transport)** — `AgentInvoker(manifest, clients=)` is the wire-level dispatcher the harness path uses in place of the Supervisor's default `invoke_fn`: it invokes a *real* leaf agent by `manifest.runtime.backend`. Four backends are live — **`callable`** (an in-process Python entrypoint, injected via `runtime.client` or imported from `runtime.entry`), **`agentcore`** (AWS Bedrock AgentCore — the `bedrock-agent-runtime` `invoke_agent` API, trace events → log stream), **`http`** (aiohttp with a urllib fallback, SSE-aware), and **`strands`** (the Strands Agent SDK) — while **`api`** is a declared stub that raises until implemented. boto3 / aiohttp / strands are all lazily imported, so importing the module needs none of them. `invoke_with_tap(prompt, inputs, context)` returns the raw response dict *plus* a live `AsyncIterator[LogEvent]` the monitor consumes; `invoke()` is the fire-and-forget form. Source: [`execute/invoker.py`](../src/concursus/execute/invoker.py).

**ExecutionMonitor + health / preemptive termination** — `ExecutionMonitor(node_id, config, event_sink=)` consumes the invoker's `LogEvent` stream concurrently and applies four rule-based per-node health strategies — **idle-timeout**, **error-threshold**, **tool-loop**, and **token-budget** (thresholds held in `MonitorConfig`, parsed per-node from the manifest's `monitor` block) — returning a `HealthSignal` (`HealthStatus` = `HEALTHY` / `DEGRADED` / `TERMINATE` / `COMPLETED`). A terminating verdict carries a stable `failure_mode` tag + structured `evidence`; the harness then raises `PreemptiveTermination`, and `remediation_for(signal)` turns that verdict into a corrective-retry prompt amendment — an overlay on the retry envelope, never a mutation of the frozen task. `DefaultMonitorFactory` builds one monitor per node and returns `None` for a node that sets `monitor: {enabled: false}` (the harness then falls back to plain `invoke()`). It only observes — it never alters a plan or reaches inside a running agent; the Supervisor keeps termination authority via the harness. Source: [`execute/monitor.py`](../src/concursus/execute/monitor.py).

**AgentHarness + HarnessFactory (the per-node wrapper)** — `AgentHarness(manifest, store, ...)` is the per-node lifecycle around one invoke: input deref (`ArtifactRef` → object-store bytes, hash-verified), prompt serialization (static context + task + rendered output contract + any remediation overlay), invoke + log-stream extraction, monitor wiring, output write (values → `ArtifactRef`s in the `ObjectStore`), and contract enforcement. `HarnessFactory(manifests, store, ...)` builds a fresh harness per attempt and exposes `make_executor()` (a `(supervisor, node, inputs, wiring) -> None` `NodeExecutor`) plus `make_kind_fn()` (routes only nodes whose manifest carries a `runtime` block to the harness kind; every other node keeps the legacy `_dispatch` path byte-for-byte). Its executor owns bounded retry — a side-effecting node gets exactly one attempt, a futility-cancelled node is never retried — and rides the Supervisor's own `validate_output` / `check_hive_contract` / `check_acceptance` gates and `record_failure` writer, so the two node-kind branches cannot drift. `make_harness_supervisor_factory(factory)` wraps it into a `GovernorLoop`-compatible `supervisor_factory`. The whole path is OPT-IN through the `NodeExecutor` seam: wire no harness factory and every node routes to the default handler — the run is byte-for-byte unchanged, and the harness never mutates the frozen `plan.order` (INV-3). Sources: [`execute/harness.py`](../src/concursus/execute/harness.py), [`execute/harness_factory.py`](../src/concursus/execute/harness_factory.py).

**ObjectStore — `FileStore` / `S3Store`** — The artifact substrate the harness reads and writes through: a two-method protocol (`get_object(uri) -> bytes`, `put_object(uri, data, content_type) -> uri`). `FileStore` maps `file://` (and, for tests, `s3://`) URIs to disk for offline / local runs; `S3Store` is the production `s3://` implementation with boto3 lazily imported on first use. Injectable, so a run is fully offline with `FileStore` and needs no AWS SDK to import. Source: [`execute/object_store.py`](../src/concursus/execute/object_store.py).

**Futility cancellation (opt-in, `cancel_futile=False` default)** — Stops in-flight work whose output can no longer be consumed. `Supervisor(..., cancel_futile=True)` arms it during a parallel wave: when a node fails, `futility_closure` (pure graph math over the frozen `plan.wiring`) computes the in-flight nodes whose output now feeds *only* the doomed downstream region, and a `CancelTokenRegistry` cancels their running harness tasks across the thread boundary; a condemned node writes its own `futility_cancelled` failed record. It is policy computation and cancel handles only — it never chooses what to dispatch, never mutates the plan (INV-3), and never judges health (the monitor's job). Default off is byte-for-byte the serial pass. Source: [`execute/futility.py`](../src/concursus/execute/futility.py).

**`execute.types` — the shared execute vocabulary** — The frozen value types the invoker, monitor, and harness pass between them: `LogEvent` (one observable event, tagged by `LogEventType` + `LogSeverity`), `HealthSignal` (+ `HealthStatus`) the monitor emits, `PreemptiveTermination` the harness raises on a terminating verdict, and `InvokeResult` (response + log stream). Plain dataclasses / enums — no AWS, no live plan handle. Source: [`execute/types.py`](../src/concursus/execute/types.py).

**Supervisor failure taxonomy + `capture_agent_binding`** — With the harness path live, `Supervisor.summary()` counts terminal failures across four classes — **`crash`** (this node's own invoke / validate / ARN-integrity failed), **`hold`** (never invoked because a producer did not complete), **`preemptive_termination`** (its monitor judged the run unhealthy), and **`futility_cancelled`** (cancelled mid-flight, output unconsumable) — each written onto the failed record's `failure_class` under `on_error='record'`. `Supervisor(..., capture_agent_binding=True)` additionally records the real per-node invoke payload for post-run capture. Both default off / inert, and neither changes that `run` is a single static forward pass over the frozen plan (INV-1). Source: [`execute/supervisor.py`](../src/concursus/execute/supervisor.py).

**AgentRuntime — the manifest's harness binding** — The typed `.agent.yaml` block that tells the harness path HOW to invoke an agent, previously present only in the raw manifest dicts the `HarnessFactory` consumes. `AgentRuntime(backend, config)` is a frozen dataclass: `backend` is typed and validated against `RUNTIME_BACKENDS` (`callable` / `agentcore` / `http` / `strands` / `api`), so a typo fails closed at `AgentManifest.validate()` rather than mid-run, while the heterogeneous per-backend keys (`entry` / `client`, `agent_id` / `alias_id`, `endpoint`, …) stay in an open `config` map the invoker validates at dispatch. The empty default is *falsy*, so a manifest with no `runtime:` block behaves exactly as before — routing to the legacy `_dispatch` path via `HarnessFactory.make_kind_fn`. `AgentManifest` also gained sibling `monitor` and `output_mapping` fields and a `to_harness_dict()` that derives the raw harness view, so one typed manifest replaces the two hand-maintained representations. Source: [`core/manifest.py`](../src/concursus/core/manifest.py).

## State: the durable substrate

A single append-only log of validated outputs, plus rebuildable projections over it. See [API Reference: state](reference/state.md) and the [Durable Run State guide](guides/durable-state.md).

**StateStore + three backends** — `StateStore` is the 4-method seam the supervisor writes through and resumes from: `put(node, output, *, meta=)`, `get(node)`, `completed()`, `records()`. Three backends implement it: `InProcessStateStore` (zero-dependency, offline default), `MemoryStateStore` (AWS Bedrock AgentCore Memory-backed, durable and resumable, boto3 imported lazily), and `FileVaultStateStore` (persists one round-trip-exact markdown note per record on disk). Writes are append-only; a content-identical re-put is a dedup no-op, never an error. Source: [`state/statestore.py`](../src/concursus/state/statestore.py), [`state/filevault.py`](../src/concursus/state/filevault.py).

**Replay-resume** — Both durable backends resume by *replay*, never by re-plan. The append-only event log is the single source of truth; the `{node: latest validated output}` projection is a derived read model rebuilt by folding the log. For `MemoryStateStore`, resume is a replay over the same `(memory_id, actor_id, session_id)`. Source: [`state/statestore.py`](../src/concursus/state/statestore.py).

**RunGraph / RunIndex / rundb / Precedent — disposable projections** — Everything derived from the log is deletable and rebuildable, never a second source of truth. `RunGraph` projects records into the data-dependency DAG (producer→consumer via `consumes` edges) for upstream/downstream blast-radius and a structural gate. `RunIndex` is the orthogonal *execution* tree (a metadata inverted index + Folgezettel materialized-path traversal over each record's address). `rundb` (`build_run_db` / `build_precedent_db`) materializes a disposable SQLite index over a run's notes. `PrecedentRetriever` is the compile-time, read-only cross-run lookup (StructuredKey → Lexical BM25 → optional Dense) that feeds `plan_from_goal`'s context. Deleting any of them loses nothing. Sources: [`state/rungraph.py`](../src/concursus/state/rungraph.py), [`state/runindex.py`](../src/concursus/state/runindex.py), [`state/rundb.py`](../src/concursus/state/rundb.py), [`state/precedent.py`](../src/concursus/state/precedent.py).

**Cross-domain precedent transfer (opt-in, default off)** — `make_hashing_embed_fn(dim=...)` is a deterministic, offline `str -> vector` embedder for the retriever's *dense* rung. Wired via `PrecedentRetriever(embed_fn=...)` (default `None` ⇒ the dense rung is skipped), it lets a novel goal retrieve a structurally-adjacent prior run to warm-start decomposition — with no heavy dependency and no model. Off by default: the retriever runs its StructuredKey → Lexical BM25 ladder alone. Source: [`state/precedent.py`](../src/concursus/state/precedent.py).

**Checkpoint compaction** — `MemoryStateStore.checkpoint()` (and `FileVaultStateStore.checkpoint()`) writes one append-only `CHECKPOINT` event carrying the compacted latest-per-node snapshot of the current epoch, then rotates the epoch forward. Raw events are never deleted (the log stays canonical); the checkpoint is a derived snapshot that only makes a *warm* resume cheaper (re-hydrate the snapshot, fold only the open-epoch tail). A missing/undecodable snapshot falls back to a full cold replay, so the fast path can never diverge from the slow one. Source: [`state/statestore.py`](../src/concursus/state/statestore.py).

**Typed run-event contract (`RunEvent` / `RunEventKind`)** — The frozen, typed SHAPE of one governor episode-boundary event — the payload the `GovernorLoop`'s opt-in `EventSink.emit` sends and its readers switch on. `RunEventKind` is the CLOSED vocabulary of kinds (`EPISODE_START`, `EPISODE_END`, `DECISION`, exposed as the bare-string frozenset `RUN_EVENT_KINDS`); `RunEvent` is a `TypedDict` (`total=False`) whose boundary-invariant keys (`type`/`run_id`/`round`/`completed`/`frontier`) always ride while per-kind extras (`done`/`progressed` on end, `route`/`terminated_by` on decision) are added only where meaningful. It is a plain-dict VALUE — never a live ctx/plan handle — so an observer can never reach inside a running Supervisor or mutate a frozen plan (INV-3). `check_run_event_alignment(emitted_kinds)` is the build-time drift guard: it raises `RunEventContractError` if an emitter ever sends a kind outside the closed set, mirroring the `check_alignment` seam the compiler uses to type-gate manifest edges — so emitter/reader drift fails at test/build time, not at runtime. Source: [`state/statestore.py`](../src/concursus/state/statestore.py).

**Coordination notices (opt-in cross-node notice; append-only, never dispatched)** — A `RecordType.COORDINATION` record is an opt-in cross-node notice written to the SAME append-only log (the sole SSOT) — never a new `StateStore` method and never mutable state. `append_coordination_notice(store, node, payload)` keys it under the dedicated `__coordination__` sentinel (NOT the referenced `node`, which would flip that node's latest-overall record) with a non-`validated` status, so it can NEVER enter `completed()` / `get()` / the validated projection and thus can never contaminate the executed prefix `recompile` pins (INV-3/INV-5). The referenced node rides in the record's `producer` field; `list_pending_notices(records, terminal_nodes)` is a PURE staleness reader that drops notices about already-terminal nodes and mutates nothing (marking one consumed is itself just another append — there is deliberately no mutable consume flag). Absent any call, the log is byte-for-byte unchanged. Source: [`state/statestore.py`](../src/concursus/state/statestore.py).

**Knowledge-transfer connector — the `slipbox_transfer` terminal node (opt-in, default off)** — The egress that turns a finished run's *episodic* notes into *permanent* external notes via a knowledge-consolidation sub-agent. Four pieces: **(C1)** `build_slipbox_transfer_manifest` / `wire_slipbox_transfer_terminal` author an MCP terminal node wired as the run's sole sink, with a fail-closed acceptance contract (`state` must be `complete`, `result_path` non-empty) that mirrors the sub-agent's real job dict; **(C4)** `register_slipbox_foundry` seeds the registry + ledger so `match_task("slipbox_transfer")` resolves it; **(C2)** `export_run_log` copies the run's episodic notes (idempotently, inode-stable) into the sub-agent's ingestion inbox, `distill_export` wires the cross-run precedent; **(C3)** `TransferTriggerSink` (composed via `FanOutEventSink`) fires the export at the strictly-outer `decision`/`route=="synthesize"` boundary, and `sweep_untransferred_runs` is the reaper/next-boot backstop. `session_overall_ok` is the rollup: a session is not green unless the transfer ran and was accepted. The contract mirrors the sub-agent's real job dict captured in `CONSOLIDATOR_JOB_DICT_KEYS` / `CONSOLIDATOR_COMPLETE_STATE`. All compile-time (C1/C4) or strictly-outer / post-run (C2/C3) — never an in-`Supervisor.run` mutation; concursus never imports the consolidation runtime (ingestion is an injected `admit_fn`). Absent any wiring, a run is byte-for-byte unchanged. See the [Knowledge Transfer guide](guides/knowledge-transfer.md). Source: [`state/transfer.py`](../src/concursus/state/transfer.py).

## Governor: runtime governance {#governor-runtime-governance}

The strictly-outer control loop that wraps the compiler and supervisor. See [API Reference: governor](reference/governor.md) and the [Governor guide](guides/governor.md).

**Governor loop** — `GovernorLoop(goal, manifests, ..., auto_create=False, create_fn=)` is the fixed cyclic outer driver: `planner → router → run_episode → collect → route_after_collect → {planner | synthesize}`. Each round forms a *fresh* frozen plan (assemble round one, `recompile` after), runs exactly one static `Supervisor` episode over it, folds outputs into the append-only log, then decides — bounded — whether to replan or synthesize. Topology is fixed and compiled once; all dynamism lives in `GovernorState` + the log. It is bounded four ways so it must terminate (frontier-exhaustion, `no_progress_n` stall, `max_rounds`, hard step-cap). LangGraph is an OPTIONAL backend imported lazily; the same node functions run via a pure-Python fallback driver when it is absent. Source: [`governor/loop.py`](../src/concursus/governor/loop.py).

**EventSink observers — `FanOutEventSink` / `NullEventSink` (opt-in, default off)** — The loop's one `event_sink` slot takes an `EventSink` that receives a plain-dict `RunEvent` VALUE at each episode boundary. `NullEventSink` is the canonical explicit no-op (behaviorally identical to leaving the slot unset); `FanOutEventSink([...])` composes several observers into the single slot, each child individually guarded (so a custom observer and the state-tier `TransferTriggerSink` — which fires the session-end transfer at `synthesize` — coexist). Observer-only: a sink reads the frozen event and writes downstream; it can never reach inside a running Supervisor or mutate a frozen plan (INV-1/INV-3/INV-5), and its exceptions are swallowed. An empty fan-out (or an unset `event_sink`) is byte-for-byte a no-sink run. Source: [`governor/loop.py`](../src/concursus/governor/loop.py).

**Live decompose→bind→align + frontier recording (opt-in, default off)** — `GovernorLoop(..., record_frontier=False, decompose=False, bind_fn=None)` adds two independent switches. With `decompose=True`, round-1 authoring runs `plan_from_goal(decompose=True)` + `staff_capability_dag(bind_fn)` instead of the single-node `plan_from_goal` + manifest reconcile — so decompose → bind → assemble is the loop's *live* behavior and cold-start runs with zero caller manifests; the staffed set is memoized (one deterministic set shared by assemble/recompile and every episode, so resume re-derives it identically, INV-4). With `record_frontier=True` and a scheduler set, the router's cleared frontier (`FrontierProposal.compile_next`) is threaded into the next round's `recompile(compile_next=…)` and recorded on the read-only `ProvisioningPlan.frontier` (emitted in `to_dict` only when non-empty; never changes order/entries/wiring) — closing the previously-dead scheduler→compiler channel on the live path, independent of the binder. `bind_fn` is the per-capability binder handed to `staff_capability_dag`. Both default off = byte-for-byte the single-shot manifest path. Source: [`governor/loop.py`](../src/concursus/governor/loop.py).

**Auto-Create on UNMATCHED (opt-in, default off)** — With `auto_create=True` and a scheduler, when the router finds `UNMATCHED` frontier roles (no standing agent serves the step) the loop invokes the spawn seam `create_fn(task) -> bool`, records spawned tasks on `ctx["created"]` (surfaced on the cockpit), then re-proposes so a now-standing agent binds. The default seam `_default_create_fn` routes `registry.ensure_task(task) → provision_agent → CreateAgentRuntime` (the real Create actuator); a fake `create_fn` is injected in tests so no AWS/boto3 is touched. Spawns happen *between* rounds, never as a live-plan mutation, and a failed or unconfirmed spawn leaves the node held (safe degradation). The default `auto_create=False` leaves an `UNMATCHED` role held, exactly as before. Source: [`governor/loop.py`](../src/concursus/governor/loop.py).

**GovernorState** — The loop's persistent outer state: the ordered *sequence* of frozen plan VALUEs by version (`plan_history`) plus a pointer to the append-only `StateStore` log — deliberately **not** a mutable plan. `advance(next_plan, ...)` swaps in a newly-assembled plan and bumps `plan_version` (mirroring `current_frozen_plan.revision`) without touching prior values; the executed prefix is always re-derived from the log, never cached mutably. Source: [`governor/state.py`](../src/concursus/governor/state.py).

**TrustLadderScheduler** — The router's per-decision matcher. `propose_frontier(plan, completed=)` returns a `FrontierProposal` VALUE (it never mutates the plan): each ready step is matched to a standing agent via the read-only `AgentRegistry`, its earned trust is read off a GOV-side ladder, and it is partitioned into one of three outcomes below. `update_trust(name, outcome)` is the *only* place trust is re-earned (GOV-side, between rounds); the create-time `evaluate_deploy_gate` is read at most once per agent as the seed. `TrustLadderScheduler(..., load_fn=)` optionally takes an availability/load signal `load_fn(name) -> int` (a bad `load_fn` is swallowed as 0). Source: [`governor/scheduler.py`](../src/concursus/governor/scheduler.py).

**Adaptive strictness dial (opt-in, default off)** — `make_trust_strictness(scheduler, *, strict_below=TrustGrade.L2_GUARDED) -> Callable[[str], bool]` closes the loop between earned trust and the compiler contract: it returns a node→bool predicate that is `True` (apply the strict contract) for any node whose serving agent's earned trust is *below* `strict_below` (WEAK/unproven — default L0/L1, and an unknown/never-seeded node is treated as WEAK so the conservative default is strict) and `False` (run lean) for a proven agent at or above the bar. Wire it as `OrchestrationAssembler(..., strict_fn=make_trust_strictness(sched))` and/or `Supervisor(..., acceptance_fn=make_trust_strictness(sched))`, realizing *strictness ∝ 1/strength* off the same Trust Ladder that governs autonomy. Author/compile-time only; exported from `concursus.governor` (not the package root). Source: [`governor/scheduler.py`](../src/concursus/governor/scheduler.py).

**Scheduler as a binder (additive, opt-in path)** — Alongside the first-match trust *gate* (`decide` / `propose_frontier`, unchanged), the scheduler also offers a candidate-set *binder* that selects a task's agent by trust and availability. `decide_ranked(node) -> Binding` pulls the *full* candidate set via `registry.match_all(node)` (not first-match `match_task`), keeps the bar-clearing candidates, and ranks them best-trust-first (tie-break: least `load_fn(name)`, then agent name for determinism); all below bar → `ESCALATE`, none serve → `UNMATCHED`. `propose_bindings(plan, *, completed, ready=)` is the binder analogue of `propose_frontier`: it reads `plan.order` (never writes), skips completed nodes, and returns `{node: Binding}` over the ready frontier. A `Binding` (frozen) records `node`, `action` (`DISPATCH`/`ESCALATE`/`UNMATCHED`), `agent`, `version`, `grade`, `bar`, `load`, the full `candidates` tuple considered, and a `reason`. This path is pure VALUE — it reads the read-only registry plus the earned ladder and mutates nothing, never touches a frozen plan, and never calls assemble/recompile. Source: [`governor/scheduler.py`](../src/concursus/governor/scheduler.py).

**Net-new role authoring** — `author_manifest(task, *, inputs=, context=, manifest_author_fn=, trust_seed=TrustGrade.L0_SHADOW)` lets the governor *create* a net-new role from a capability gap — authoring its prompt/tools/schema — rather than only provisioning from a hand-declared manifest. With no `manifest_author_fn` (default) it returns a deterministic `_skeleton_manifest`: a valid, provisionable container-hosted HTTP `AgentManifest` with a placeholder `container_uri`, `entry`, `capabilities=[task]`, and a minimal non-empty `contract.outputs` type gate, seeded at a low trust grade (`L0_SHADOW`). With an injected `manifest_author_fn(task, context)` (the LLM seam, returning an `AgentManifest` or a `from_dict` mapping) the result is coerced and always passes `AgentManifest.validate()`. Empty task or invalid author output raises `ManifestAuthorError`. A freshly authored agent enters at `L0_SHADOW` and must earn autonomy on the Trust Ladder before it can dispatch a side-effecting task. Source: [`governor/authoring.py`](../src/concursus/governor/authoring.py).

**Capability staffing — decompose→bind front (opt-in, default off)** — `staff_capability_dag(dag, *, bind_fn=None, manifest_author_fn=None, trust_seed=TrustGrade.L0_SHADOW)` turns an agent-agnostic *capability* `AgentDAG` (from `plan_from_goal(decompose=True)` — nodes + edges but no manifests, no `depends_on`) into an assemblable manifest set. Per node it synthesizes a manifest keyed by the node id — bound to a standing agent via `bind_fn(node) -> agent-name-or-None`, else an authored `L0_SHADOW` skeleton via `author_manifest` — and derives its data-wiring from the DAG edges (one input per upstream producer, fed by `"<producer>.result"`). This makes the cold-start path work end-to-end: decompose → staff → assemble freezes a real multi-node plan with **zero hand-authored manifests**. Pure/offline (INV-2); `bind_fn=None` authors every node. Source: [`governor/authoring.py`](../src/concursus/governor/authoring.py).

**Compiler as regulator — reject-and-rebind (opt-in, default off)** — `staff_with_rebind(dag, candidates_fn, *, assembler=None, max_rebinds=8)` upgrades the compiler from a weak regulator (validate only) into a real one (reject *and* re-bind). Given `candidates_fn(node) -> [AgentManifest, ...]` best-first (`CandidatesFn` is the ranked-candidates seam), it strict-assembles and, on an `AlignmentError`, advances the **offending producer** (falling back to the consumer) to its next candidate and retries — a bounded author-time search (`max_rebinds`, INV-2) enabled by the `.node`/`.producer` attributes the error now carries. It returns the type-aligning manifest set, or raises `RebindExhausted` (a `ValueError`) if none aligns within the bound. Source: [`governor/authoring.py`](../src/concursus/governor/authoring.py).

| Outcome | Constant | Meaning |
|---|---|---|
| Dispatch | `DISPATCH` | Earned trust meets the bar — cleared to compile next |
| Escalate | `ESCALATE` | Below bar (or side-effecting under `require_approval`) — held, not dispatched |
| Unmatched | `UNMATCHED` | No standing agent serves the step — needs provisioning |

**AgentRegistry / AgentVersion** — `AgentRegistry` is the governor's read-only *process table*, derived from the shipped `DeployLedger`. It answers "which standing agent, at which version, can do task X right now?" — a dispatch-time question the content-identity ledger does not. Each distinct fingerprint for a name is one `AgentVersion` (1-based, newest is current); `match_task` considers only the current version. The registry never writes the ledger — `spawn`/`fork`/`ensure_task` delegate to `provision_agent`. Source: [`governor/registry.py`](../src/concursus/governor/registry.py).

**ScopeAddress** — A frozen point in the `org → portfolio → program → task` scope stack, above the single-run unit. `push()` returns a new address (never mutates); `program_key()` gives the `org.portfolio.program` prefix that rolls runs up by program. Scope adds read-only cross-program synthesis (`build_programs_index`, `director_leverage_view`) over per-run precedent notes — it selects, seeds, and dispatches nothing. Source: [`governor/scope.py`](../src/concursus/governor/scope.py).

**KTLODaemon** — A standing "keep-the-lights-on" daemon above the loop. It monitors a live `EventSource` (+ optional drift detector), triages each signal (`TRIAGE_CLOSE` / `TRIAGE_INVESTIGATE` / `TRIAGE_ESCALATE`), and dispatches one *fresh* bounded `GovernorLoop` episode per triggered investigation. `LAUNCH` (drain once, then stop) vs `KTLO` (standing, bounded by `max_ticks`) is config on the same machinery. It only enqueues episodes — it never reaches inside a running `Supervisor`, and a failing episode is recorded while the daemon survives. Source: [`governor/ktlo.py`](../src/concursus/governor/ktlo.py).

**DirectorCockpit** — A read-only director view over one run's shipped read models, composed from nothing but `summary()`/`index()`/render calls: `briefing()`, `exception_queue()`, `runs_monitor()`, `snapshot()`/`follow()`, `family_tree()`. It selects nothing, seeds nothing, schedules nothing — it re-derives every view from the append-only log on each call. Usually obtained via `GovernorLoop.cockpit()` after a run. Source: [`governor/cockpit.py`](../src/concursus/governor/cockpit.py).

**ControlSurface + verb taxonomy (opt-in, read-mostly, offline-by-default)** — Where `DirectorCockpit` gives a HUMAN director read-only projections, `ControlSurface` gives a governed AGENT a narrow, in-process (NOT HTTP) handle over the same SSOT. Verbs split by blast radius: **`READ_VERBS`** (`query_plan`, `tail_log`, `search_runs`, `precedents`) are ALWAYS on — pure projections over the frozen plan, the append-only log, the run-db FTS, and durable precedents; they mutate nothing and need no authorization. **`ACTUATING_VERBS`** (`deploy`, `run`, `recompile`) each route THROUGH an EXISTING actuator only (the surface owns no side-effect logic; `recompile` is additionally `RECURSIVE_VERBS`). Availability is resolved from the compiled `ControlScope` (`ControlScope.from_plan` — authorizes NO actuating verb by default), NOT an env var: a verb the scope did not authorize is ABSENT (`invoke` raises rather than routing — non-registration, no bypassable deny stub). A present actuating verb is further gated by an explicit `activate()` arm, and any requested `TrustGrade` is CLAMPED down to the compiled ceiling (`effective_trust`), never above it. Actuators are injected thunks — a surface with none is fully read-only + offline. Sources: [`governor/cockpit.py`](../src/concursus/governor/cockpit.py), [`governor/scope.py`](../src/concursus/governor/scope.py).

**IdleRuntimeCuller (opt-in, computes-only — teardown is the caller's)** — A PURE, default-off housekeeping gate for a standing fleet that accretes idle runtimes. `cull(last_active, now_ts, *, active=, tiers=)` is a TOTAL, DETERMINISTIC function with NO I/O — it reads no registry/ledger/plan and mutates nothing — returning only the `Set[str]` of idle runtimes eligible to reclaim; the caller performs teardown, and a reclaimed runtime re-provisions on its next invoke from the content-keyed `DeployLedger` row. Two idle floors (LONG for a `standing`-tier or most-recently-active runtime, SHORT otherwise), with two defenses: (1) NEVER cull an in-flight (`active`) runtime, and (2) cull only once WALL-CLOCK `elapsed >= floor` — a short or drift-induced negative elapsed reschedules (keeps), never reclaims. It is emphatically NOT wired into `Supervisor.run` (INV-3): culling is a strictly-outer, between-episode decision, never an in-episode plan mutation. Source: [`governor/ktlo.py`](../src/concursus/governor/ktlo.py).

## Reasoning: bounded deliberation, before the freeze

The plan-formation organ — it forms a plan by bounded reasoning *strictly before* `assemble`, and is never wired into `Supervisor.run`. See [API Reference: reasoning](reference/reasoning.md) and the [Reasoning guide](guides/reasoning.md).

**HypothesisTrail** — The durable, replayable `.3` reasoning-branch store. It records a deliberation as a tree of hypotheses (each closed by a verdict: `ACCEPT` / `REJECT` / `UNDEC`) into an append-only JSONL log, and computes Dung grounded-semantics labels (`in` / `out` / `undec`) over an attack graph. A verdict and its resolved marker commit atomically in one file replace; `open_frontier(root)` returns the un-resolved leaves — an empty frontier means the debate has converged. It dispatches nothing. Source: [`reasoning/trailstore.py`](../src/concursus/reasoning/trailstore.py).

**DKSEngine + CCS bands** — `DKSEngine` is the bounded, cyclic deliberation state machine that drives one `HypothesisTrail` through the 8-node `observe → name → structure → operationalize → test → challenge → improve → compile` cycle with a confidence-gated loop-back. The Confidence-Coherence Score `CCS = α·llm_conf + β·homophily + γ·coherence` (defaults `α=0.5, β=0.25, γ=0.25`, held in `CCSWeights`) routes each decision into a band via `route_by_confidence`. Both the LLM investigator and an optional LangGraph backend are lazily-injected seams — it runs end-to-end with neither installed. Source: [`reasoning/dks_engine.py`](../src/concursus/reasoning/dks_engine.py).

| CCS | Band | Behavior |
|---|---|---|
| `>= 0.85` | `BAND_AUTO_ACCEPT` | Single-agent auto-accept |
| `0.50 – 0.85` | `BAND_ARGUE_COUNTER` | Two-agent argue + counter (fires the counter-argument seam on CHALLENGE) |
| `< 0.50` | `BAND_ESCALATE` | Human escalation |

**InnerGraph** — The parallel hypothesis-investigator dispatch layer: a fresh, disposable per-round projection of the open frontier. `compile_inner_graph` snapshots the frontier into bounded fan-out batches; `dispatch_frontier` runs one injected investigator per hypothesis through a bounded thread pool, merges results order-insensitively (a worker failure is data, not an exception), and digests each to the `.2` worker-log lane. It is confined to `.2` and never writes a `.3` verdict (that is the engine's job). Source: [`reasoning/inner_graph.py`](../src/concursus/reasoning/inner_graph.py).

**deliberate: `seed → form_plan → lower_to_dag`** — The top-of-tier driver that forms a plan by deliberation and lowers the converged conclusion into a frozen `AgentDAG`. `seed(trail, goal, retriever=)` seeds the `.3` root from a goal (optionally warm-starting by reusing a strong retrieved precedent's steps as confident children). `form_plan(trail, goal, ...)` runs the bounded `SEED → READ → DISPATCH → DIGEST → VERDICT → RE-READ` loop to convergence, then lowers. `lower_to_dag(trail, root, ...)` is a pure deterministic fold: only `in`-labelled hypotheses become DAG nodes, and it may run only over a *converged* debate (else `ThreadNotResolved`). The resulting DAG is handed to `OrchestrationAssembler.assemble`. Source: [`reasoning/deliberate.py`](../src/concursus/reasoning/deliberate.py).

## Invariants

The load-bearing rules the whole system codes against. State them, do not weaken them.

1. **Compiler, not a runtime governor.** A run is `AgentDAG → assemble → frozen ProvisioningPlan → Supervisor.run`: a single forward pass over an immutable plan. `assemble` produces a value; `Supervisor.run` is one static forward pass over it and never mutates the plan.

2. **Strictly before assemble.** Every generative or mutating step — reasoning (`deliberate`, `DKSEngine`), planning (`plan_from_goal`), a governor round — happens *strictly before* `assemble`. `recompile` is the only sanctioned plan mutation, and it emits a new frozen superset plan *around* the compiler; resume is replay of an append-only log, never a re-plan mid-flight.

3. **The governor loop is strictly outer.** It never reaches inside a running `Supervisor` and never mutates a frozen plan. Frozen plans are values swapped by version; growth between episodes happens only via `recompile` (which may add, never drop — `MonotonicityError` otherwise).

4. **The append-only log is the single source of truth.** The `{node: latest validated output}` projection — and `RunGraph`, `RunIndex`, `rundb`, the precedent hub, the deploy ledger, and every cockpit/registry/scope view — are rebuildable, disposable derivations re-derived from the log each time. A re-put is a new record, never an in-place edit; a checkpoint is a derived compaction, never a mutation or deletion. There is no `set_output`-style in-place edit anywhere.

5. **Deliberation is bounded and terminating.** Every reasoning loop stops when the open frontier empties (converged) or its round/step budget is spent; `DKSEngine`, `form_plan`, `recompile` (`max_revisions`), and `GovernorLoop` (frontier-exhaustion / stall / `max_rounds` / hard step-cap) are all bounded so they must terminate in a frozen plan.

> **The opt-in additions are default off, and the compiler identity is unchanged.** The flexibility & robustness layer completed in v0.6.0 — goal decomposition (`decompose=True`), capability staffing (`staff_capability_dag`) and reject-and-rebind (`staff_with_rebind`), the scheduler-as-binder path (`decide_ranked` / `propose_bindings`), the `recompile` `compile_next` channel and advisory `ProvisioningPlan.frontier`, net-new role authoring (`governor.authoring`), auto-Create on `UNMATCHED` (`auto_create=True`), and the cross-domain precedent-transfer embedder (`make_hashing_embed_fn`, wired via `PrecedentRetriever(embed_fn=)`) — every one defaults **off**, so shipped behavior is byte-for-byte unchanged and Invariants 1–5 all still hold. The binder never mutates a frozen plan or calls assemble/recompile; `compile_next` only annotates the advisory frontier and never changes `order`/`entries`/`wiring`; auto-Create spawns *between* rounds, never as a live-plan mutation; a freshly authored agent enters at `L0_SHADOW` and must earn autonomy before dispatching a side-effecting task.
>
> The three-property compiler contract (non-overlap `single_writer`, deep-type `strict_types`, output-QA `check_acceptance` / `check_hive_contract`), its per-agent `strict_fn` / `acceptance_fn` dial and the `make_trust_strictness` predicate, and `GovernorLoop(decompose=True, bind_fn=…, record_frontier=True)` all default **off** and are compile/author-time or run-side gates only. Turning them on can only *reject* an unsafe plan or output (never admit or mutate one): the contract gates are pure compile-time checks (INV-2), rebind is a bounded author-time search that re-freezes before dispatch, an output-QA/OS-boundary miss is recorded-failed and earns no trust (INV-1, INV-4), and `record_frontier` only annotates the advisory `frontier`. The one behavioral change — `AgentDAG.nodes` now returns topological rather than alphabetical order — is a stricter dispatch guarantee, not a relaxation, and leaves INV-1..5 intact.
>
> The opt-in manifest metadata (`capabilities`, `contract_version`, `context_mode`) is stored + shape-validated but never acted on — every empty default is byte-for-byte a manifest that omits it. The typed run-event contract (`RunEvent` / `RunEventKind`) and `RecordType.COORDINATION` notices are plain-dict / append-only VALUES that no observer can use to reach inside a running Supervisor or perturb the executed prefix `recompile` pins (INV-3/INV-4). The `ControlSurface` + verb taxonomy is read-mostly and offline-by-default — actuating verbs are absent unless the compiled `ControlScope` authorized them, and then are gated by an explicit activation arm + monotonic TrustGrade clamp; `IdleRuntimeCuller` computes a reclaim SET only and is never consulted inside `Supervisor.run` (INV-3). Bounded antichain parallelism (`run(parallel>1)`) and its `min(pref, capacity)` fan-out clamp are still a single static pass over the frozen `plan.order` — they change only *when* independent nodes dispatch and how wide the worker pool is, never the dispatched node set, so the store is byte-for-byte identical to the serial pass; the node-executor registry defaults to the single dispatch path. Every one preserves Invariants 1–5, and a run with none turned on is unchanged: `AgentDAG → assemble → frozen ProvisioningPlan → Supervisor.run` remains one forward pass over an immutable plan.

> **The knowledge-transfer connector (`state.transfer`) preserves the compiler identity.** Its C1/C4 pieces are compile-time (author a manifest, wire the DAG, seed the registry/ledger — all strictly *before* `assemble`); the `slipbox_transfer` node then runs as a normal terminal node in the single forward pass, and its fail-closed acceptance gate rides `Supervisor`'s own opt-in `check_acceptance` seam — it only *rejects* (records-failed, reject-not-admit), never mutates the plan (INV-1). C2's export reads the finished log / on-disk notes and writes an EXTERNAL target, never re-putting a `Record` (INV-4). C3's `TransferTriggerSink` observes the frozen `decision` VALUE strictly *between* episodes and the reaper/next-boot sweep is a separate post-run pass (INV-3); the rollup is a pure read. concursus never imports the consolidation runtime, and the success marker is a non-`.md` sentinel invisible to the loaders — so wiring none of it leaves the default pass byte-for-byte unchanged.
